LangGraph classroom deck

State, reducers, invoke, pause, resume

A practical walkthrough of how graph state works in chat applications and parallel workflows.

Students should leave knowing

  • Why `Annotated` appears in state schemas.
  • Why reducers are required for concurrent writes.
  • How chat requests call `invoke` or `stream`.
  • How pause and resume work with checkpointed threads.
The big idea

LangGraph nodes return state updates, not mutations

Inputnew user event
Node Areturns partial state
Node Breturns partial state
Runtimemerges writes
Checkpointstate is saved

Teaching note: separate what user code does from what the runtime does. A node says, "here is my update." The runtime decides how that update changes the shared state.

State schema

The schema describes keys and merge behavior

Every state key is backed by a channel. If you do not specify merge behavior, LangGraph uses replacement semantics.

from typing import Annotated
from typing_extensions import TypedDict
from langgraph.graph import add_messages

class State(TypedDict):
    messages: Annotated[list, add_messages]
    search_results: Annotated[list[str], operator.add]
    status: str
Annotated

`Annotated` means type plus metadata

Python typing 
from typing import Annotated

field: Annotated[list[str], "metadata"]

The real type is still `list[str]`. The extra value is metadata for tools and frameworks.

LangGraph usage 
items: Annotated[list[str], operator.add]

LangGraph reads the metadata and treats `operator.add` as the reducer for `items`.

Default behavior

Plain fields allow one write per step

Without a reducer, LangGraph cannot safely choose between two competing updates.

Node A 
{"status": "approved"}
Node B 
{"status": "rejected"}
Runtime result

Invalid concurrent update. The field needs one writer or an explicit reducer.

Reducers

A reducer is a merge function

Its shape is always current value plus new value gives next value.

def reducer(current, update):
    return next_value

class State(TypedDict):
    items: Annotated[list[str], reducer]
Example

List accumulation with `operator.add`

Node A writes 
{"items": ["a"]}
Node B writes 
{"items": ["b"]}
Reducer result 
operator.add([], ["a"])       # ["a"]
operator.add(["a"], ["b"])   # ["a", "b"]
Why this matters

Reducers make parallel graph execution explicit

1

Concurrent writes

Fan-out nodes can write the same key in the same step.

2

Incremental state

Nodes return deltas instead of rebuilding the full state.

3

Replay safety

Checkpointed writes can be folded back into state.

Messages

`add_messages` is a special reducer for chat

It appends new messages, replaces messages with the same ID, and supports removal semantics.

from langgraph.graph import add_messages

class State(TypedDict):
    messages: Annotated[list, add_messages]

def chatbot(state: State):
    return {
        "messages": [
            {"role": "assistant", "content": "Hello"}
        ]
    }
Chat request design

One chat request sends one new event

Browsermessage text
API routethread_id
graph.invokenew message only
Checkpointerloads history
Responsestate or stream

The frontend usually does not resend the whole conversation. The checkpoint stores history, and `add_messages` merges the new user message into it.

Invoke

`invoke` continues the thread identified by config

The graph definition is shared. The `thread_id` selects the persisted conversation or workflow run.

config = {
    "configurable": {
        "thread_id": "chat-123",
        "user_id": "user-7",
    }
}

result = graph.invoke(
    {"messages": [{"role": "user", "content": text}]},
    config=config,
)
Streaming

Chat apps often prefer `stream`

`invoke`

Runs until the graph finishes or interrupts, then returns the final result.

`stream`

Runs the same graph but lets the backend forward messages, tokens, or events as they arrive.

for chunk in graph.stream(input, config=config, stream_mode="messages"):
    send_to_browser(chunk)
Pause and resume

A paused workflow is checkpointed, not frozen in memory

Runnode executes
interrupt()asks for input
Checkpointstate saved
User actionapproval or data
Resumesame thread_id

This is why other requests can continue while one workflow waits for a person. The waiting run is represented by persisted state and execution metadata.

Resume command

Resume targets one paused thread

The same `thread_id` is the address of the paused workflow.

from langgraph.types import Command

graph.invoke(
    Command(resume={"approved": True}),
    config={
        "configurable": {
            "thread_id": "chat-123"
        }
    },
)

Classroom exercise

Predict the final state

Ask students what happens after the two nodes write in the same step.

class State(TypedDict):
    logs: Annotated[list[str], operator.add]
    status: str

node_a -> {"logs": ["A"], "status": "draft"}
node_b -> {"logs": ["B"], "status": "final"}
Expected answer

`logs` can merge to `["A", "B"]`. `status` conflicts because it has no reducer and receives two writes in one step.

Design checklist

Questions before building a graph

State
  • Which keys are replaced?
  • Which keys accumulate?
  • Which keys may receive concurrent writes?
Runtime
  • What is the `thread_id`?
  • Where are checkpoints stored?
  • Can the workflow interrupt and resume?
Summary

The mental model

Nodes emit updates. Reducers merge updates. Checkpoints persist threads. `invoke` or `stream` advances one thread at a time.

`Annotated`

Attaches metadata to a type.

Reducer

Defines how multiple writes become one state value.

`thread_id`

Identifies which workflow state to load or resume.
