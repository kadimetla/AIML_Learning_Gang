chat_memory_skills · 03 · chat.py build_graph()

This is the whole graph, built in chat.py build_graph(). recall always runs first and reads long-term memory. agent calls the model. If the model asked for tools, tools_condition sends us to the tools node, and the edge from tools goes straight back to agent. That loop repeats until the model answers in plain text, which goes to END. Point out that the loop is only two lines of code: add_conditional_edges and add_edge("tools", "agent").

chat_memory_skills · 04

To LangGraph these are all just tools in one ToolNode. The difference is what they are for. Capabilities fetch or compute. Skill tools return text that tells the model what procedure to follow. Memory tools write to the long-term store. The model picks all of them the same way: from their names and docstrings.

chat_memory_skills · 05 · memory.py, chat.py open_stores()

This table is the heart of the lesson. Short-term memory needs zero code from us: pass a checkpointer to compile and LangGraph saves and reloads the message list per thread_id. Long-term memory is ours: the model writes facts with save_memory, and the recall node reads them back by meaning, not by exact words. Step 4 is the one to stress. Once the checkpointer and store are attached at compile time, LangGraph handles saving history, and any node or tool can reach the store with get_store(). chat_memory_skills · 07 · chat.py chat_turn(), memory.py recall()

Step 1: the two ids in the config are the only thing that connects this run to the past. thread_id selects the conversation, user_id selects the person. Step 2 happens without any code of ours. Step 3 is a semantic search: the user's message is embedded and compared with the stored facts, and only this user's namespace is searched.

chat_memory_skills · 08 · chat.py agent_node(), build_graph()

Steps 4, 5 and 6 repeat as many times as the model needs. Each pass through agent is one LLM call. The model never runs a tool itself: it only asks, and ToolNode runs the Python function and hands the result back as a ToolMessage. Step 7 is again free: we never call save.

Skills · progressive disclosure

Read only as much as the request needs

Discover

At startup: each SKILL.md’s name and description go into the prompt

Load

The model calls load_skill(name) and gets the full SKILL.md

Drill

read_skill_file for references/ files, only when SKILL.md says so

Act

The skill names the tool to call, like lookup_order

Cheap by default: every prompt holds one line per skill. The full instructions cost tokens only on the turns that use them.

Part 2 · the web version

The graph
doesn’t change.

AG-UI and CopilotKit replace only the outer loop: input, output and transport.

This is the one sentence to remember from part 2. Everything we just walked through, recall, agent, tools, both memories, the skills, is reused as is. The web version imports build_graph() from chat.py. What changes is how a message gets in and how the answer gets out.

chat_memory_skills · 14 · web/app/page.tsx, route.ts, server.py

Three processes when you run it: Next.js serves both the browser page and the runtime route on port 3000, and server.py runs on 8000. Why the runtime in the middle? The browser only talks to its own site; the agent URL and any secrets stay on the server, and the runtime is where real auth would go. AG-UI does for agent-to-UI roughly what MCP does for agent-to-tools: a standard so either side can be swapped.

Security note

Identity is a server decision

In this demo

The browser’s user picker sends user_id as properties → forwardedProps → server.py.

Fine for class: we want to switch users.

In a real app

The server reads the login session or token and sets user_id itself.

Never trust a user id the browser sends.

Otherwise anyone can type another name and read that person’s memories.

chat_memory_skills · 17 · server.py agent_endpoint()

Make this concrete: open the web app, pick user demo, ask what it knows about you. Now imagine the dropdown is a text box. Anyone could type any name. Long-term memory is personal data, so the key to it must come from authentication on the server, the one place the user cannot edit.
