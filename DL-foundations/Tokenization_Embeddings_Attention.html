Step 1 · Tokenization

Why subwords? The three options

Neural nets only process numbers — so text must be chopped into discrete units first.

✕ Out-of-vocabulary

Whole words

Unbounded vocabulary — typos, names, made-up words break it.

"teacherification" → ???
✕ Sequences too long

Characters

No OOV problem, but the model must assemble meaning from tiny pieces.

T-e-a-c-h-e-r → 7 tokens
✓ Best of both

Subwords

Common words stay whole; rare words split into reusable fragments.

teach + ##er → 2 tokens
Step 1 · Tokenization

How the vocabulary gets built

BPE / WordPiece is trained once, separately, before the model — pure frequency counting, no meaning involved.

1

Start with characters

t · e · a · c · h · e · r — every character is its own token

2

Count frequent pairs

Scan the corpus: which adjacent token pairs co-occur most often?

3

Merge the top pair

"t"+"e" → "te", then "te"+"a" → "tea" … repeated thousands of times

4

Stop at target size

Halt once vocabulary reaches ~30,000–50,000 entries.

Key point: "##er" becomes its own token simply because "X+er" patterns were extremely common — not because anyone taught the algorithm grammar.

Step 2 · IDs & Lookup

The embedding matrix: one row per token

Why we need an ID

  • An ID is just an address — "go look up row #2891."
  • The number itself carries no meaning; it's a consistent key, not a value.
  • Same token → same ID, every time — this consistency is what lets one embedding be learned per token.
vocab = { "the": 101, "teach": 5234, "##er": 2891, "graded": 9102 }

embedding_matrix.shape = (vocab_size, embedding_dim)

101
the → [ ... 768 learned numbers ... ]
5234
teach → [ ... 768 learned numbers ... ]
2891
##er → [0.13, -0.42, 0.91, ..., 0.07]
9102
graded → [ ... 768 learned numbers ... ]

Row 2891 IS the embedding of "##er" — pure lookup, no computation.

Step 3 · Learning

How embeddings actually get learned

Masked Language Modeling (BERT-style): hide a token, predict it, correct the embeddings.

1 · Mask

"The teach [MASK] graded papers"

2 · Predict

Model outputs a probability over all ~30K vocab tokens.

3 · Compare

True answer = "##er" — compute cross-entropy loss.

4 · Backprop

Gradient flows back into embedding["##er"] and neighbors.

Why repetition makes it meaningful, not random

  • "##er" appears after thousands of different stems (teach, play, fast, sing…) across the corpus.
  • Each time, the gradient nudges its vector toward whatever makes prediction more accurate.
  • Random nudges in inconsistent directions cancel out; consistent statistical patterns survive and accumulate.
  • The surviving vector is the cheapest (lowest-loss) compromise that's useful across all of "##er"'s real contexts.
Step 4 · Attention

Toy example: "teach" + "##er"

Using 4-dimensional vectors (real models use 768+) so every number is traceable.

Raw embeddings (lookup)

embedding("teach") = [0.9, 0.1, 0.2, 0.8] embedding("##er") = [0.1, 0.9, 0.7, 0.1]

Interpretation (illustrative)

"teach" points toward a "verb / action" direction in vector space.
"##er" points toward an "agentive suffix" direction.

Q, K, V — three learned projections

Query (Q)

"What am I looking for?"

Key (K)

"What do I offer to others?"

Value (V)

"What information do I actually carry?"

Step 4 · Attention

Computing the attention score

TokenQuery (Q)Key (K)Value (V)
"teach"[0.8, 0.2, 0.1, 0.3][0.7, 0.1, 0.2, 0.4][1.0, 0.3, 0.0, 0.5]
"##er"[0.2, 0.8, 0.6, 0.1][0.1, 0.9, 0.5, 0.2][0.2, 1.0, 0.4, 0.1]

Score = Query(##er) · Key(token) — dot product

score(##er → teach)

= (0.2×0.7)+(0.8×0.1)+(0.6×0.2)+(0.1×0.4) = 0.14+0.08+0.12+0.04 = 0.38

score(##er → ##er)

= (0.2×0.1)+(0.8×0.9)+(0.6×0.5)+(0.1×0.2) = 0.02+0.72+0.30+0.02 = 1.06

Higher score = the model judges this token more relevant to attend to.

Step 4 · Attention

Softmax → weighted sum → new vector

1. Softmax the scores: softmax([0.38, 1.06]) ≈ [0.34, 0.66]
"##er" places 34% of its attention on "teach" and 66% on itself.

2. Weighted sum of Values → new representation of "##er"

new_##er = 0.34×[1.0, 0.3, 0.0, 0.5] + 0.66×[0.2, 1.0, 0.4, 0.1] = [0.34, 0.10, 0.00, 0.17] + [0.13, 0.66, 0.26, 0.07] = [0.47, 0.76, 0.26, 0.24]

BEFORE (raw lookup)

[0.1, 0.9, 0.7, 0.1]

Same every time "##er" appears

AFTER (post-attention)

[0.47, 0.76, 0.26, 0.24]

Shifted toward "teach" — context-specific

Recap

Static embedding vs. contextual representation

Word2Vec-style embeddingTransformer token embedding
UnitWhole wordSubword piece (word or fragment)
Trained byPredicting neighbor words for that word alonePredicting next/masked token, jointly with all weights
Standalone meaning?Yes — reflects typical contextNo — only a starting point
Changes with context?Never — fixed foreverYes — reshaped by attention every layer

The big picture

  • Tokenization splits text into reusable, frequency-discovered pieces — no OOV problem, manageable sequence length.
  • The embedding matrix is just a trainable lookup table — one row per vocabulary ID, learned end-to-end via backprop.
  • Attention (Q·K → softmax → weighted V) reshapes each token's vector using every other token in the sequence.
  • Meaning isn't stored in any single embedding — it emerges from repeated context-mixing across layers.
