The Representation Problem

How do we turn words into numbers that capture meaning?
One-Hot Encoding (the old way)
cat = [1, 0, 0, 0, 0, … 0] (70,000 dim) dog = [0, 1, 0, 0, 0, … 0] king = [0, 0, 1, 0, 0, … 0]
✗ Vocabulary-sized vectors (50k–100k dims)
✗ All words equidistant — no similarity
✗ cat and dog have 0 relationship
✗ Sparse: mostly zeros, wastes memory
✗ No meaning — just identity tags
→
Dense Embeddings (the goal)
cat = [0.2, -0.4, 0.7, 0.1, …] (300 dim) dog = [0.3, -0.3, 0.8, 0.2, …] king = [0.6, 0.1, 0.2, 0.9, …]
✓ Compact (100–1024 dims typical)
✓ cat and dog vectors are CLOSE
✓ Meaning encoded in vector position
✓ Dense: every dimension carries info
✓ Vector arithmetic on meaning works

Word2Vec: Learning from Context

Trask Ch.11 — "Fill in the blank" trains richer word meanings than labels alone
Skip-Gram
Given a word → predict surrounding context
"sat" → predict: the, cat, on, the
Good for rare words. Slower training.
CBOW (Continuous Bag of Words)
Given context words → predict the middle word
[the, cat, on, the] → "sat"
Faster. Better for frequent words.
Why "fill in the blank" works (Trask Ch.11)
Words in similar contexts get similar weights → similar vectors. "terrible" and "horrible" both predict/are-predicted-by words like "acting", "plot", "film" → their vectors cluster. The loss function's objective forces the hidden layer to encode linguistic relationships. Meaning is derived from loss.
print(similar('terrible')) → [('horrible', -2.8), ('brilliant', -3.0), ('pathetic', -3.5), ('phenomenal', -3.7)]

GloVe: Global Vectors for Word Representation

Stanford 2014 — Uses the ENTIRE corpus co-occurrence matrix, not just sliding windows
How GloVe Works
1
Build co-occurrence matrix X
X_ij = how often word i appears near word j across the whole corpus
2
Weight rare vs common pairs
f(X_ij) caps the influence of very frequent pairs like "the", "a", "is"
3
Optimize: wᵢᵀwⱼ + bᵢ + bⱼ ≈ log(X_ij)
Dot product of word vectors ≈ log co-occurrence count
4
Result: dense vectors with geometry
Words that co-occur often → similar vectors → analogy arithmetic works

GloVe Objective Function — Unpacked

Every term in the loss function has a specific linguistic purpose
J = Σᵢⱼ  f(Xᵢⱼ)  ·  (wᵢᵀwⱼ + bᵢ + bⱼ − log Xᵢⱼ)²
Xᵢⱼ
Co-occurrence count
How many times word i and word j appear together across the full corpus. GloVe calls this "global" statistics — every word pair in every document contributes.
f(Xᵢⱼ)
Weighting function
Caps the contribution of very frequent pairs. "the" and "a" co-occur with everything — without this they dominate. f(x) = (x/100)^0.75 for x < 100.
wᵢᵀwⱼ
Dot product of word vectors
The model predicts log co-occurrence using the dot product. At optimum, this equals log(X_ij). Similar words → high dot product → close in vector space.
bᵢ + bⱼ
Bias terms
Per-word bias scalars. Words that are globally common (like "movie" in a film corpus) get a high bias, preventing confusion with pairwise semantic similarity.

BM25: The Gold Standard Sparse Retrieval

Published 1994. Still beats neural models on specific query types in 2025.
BM25(D,Q) = Σₜ  IDF(t) · f(t,D)·(k₁+1) / [f(t,D) + k₁·(1 − b + b·|D|/avgdl)]
IDF(t)
Inverse Document Frequency
log(N/df_t) — rare words across corpus get higher weight. "the" scores ≈ 0; "photosynthesis" scores high. Penalizes stop words automatically.
f(t,D)
Term frequency in document
Raw count of term t in document D. More = higher relevance, but saturates with k₁ (1.2–2.0) so 100 occurrences ≠ 100× better than 1.
|D|/avgdl
Document length normalization
Longer docs naturally contain more words. b (usually 0.75) controls how much to penalize longer docs, preventing them from dominating unfairly.
k₁, b
Tunable hyperparameters
k₁ = term frequency saturation (1.2–2.0). b = length normalization (0–1). No training needed — set by domain knowledge.

ColBERT: Late Interaction — The Third Mode

Token-level matching: more precise than a single vector, cheaper than cross-encoders
Single-vector (standard dense)
Query → 1 vector Doc → 1 vector Score = cosine(q_vec, d_vec) Fast but lossy: a 500-word doc compressed to one 1024-dim point.
ColBERT late interaction
Query → N token vectors Doc → M token vectors Score = Σᵢ max_j(qᵢ · dⱼ) Each query token finds its best matching doc token. Much more granular.
Why it matters
Precision for long documents
A 500-page technical doc has many topics. Token-level matching finds the exact paragraph relevant to the query, not just "this doc is about ML."
Handles polysemy better
Query "bank" (financial) matched token-by-token: "bank deposit" tokens score high; "river bank" tokens score low — within the same doc.
Higher accuracy, more memory
Stores N×M vectors per doc. Needs a vector DB supporting multi-vector search (Vespa, Qdrant). Worth it for high-precision RAG.
BGE-M3 produces it for free
The same forward pass that gives dense + sparse also gives ColBERT vectors. No extra model, no extra cost.

Reciprocal Rank Fusion (RRF)
RRF(doc) = Σ 1/(60 + rankᵢ)
k=60 means rank-1 and rank-2 are treated similarly. No score normalisation needed — ranks from any retriever are directly comparable. Simple and robust.
